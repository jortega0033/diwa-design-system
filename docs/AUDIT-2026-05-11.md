# Diwa Design System — Comprehensive Audit Report

**Date:** May 11, 2026  
**Auditors:** Diwa DS SDLC Lead · Web Components Engineer · Storefront Developer · Wrapper Maintainer · Accessibility Auditor · QA Tester · Release Automator · Technical Writer  
**Branch:** `main`  
**Scope:** All packages in `jortega0033/diwa-design-system`

---

## Executive Summary

Eight specialist agents conducted parallel audits across CI/release, Stencil web components, storefront docs, framework wrappers, WCAG 2.1 AA compliance, test coverage, release automation, and documentation quality. The audit surfaced **4 P0 blockers**, **17 P1 high-severity issues**, **24 P2 medium-severity issues**, and **13 P3 low-severity items**.

The most critical risks are:

1. **Every automated deploy currently lands on the wrong Firebase project** — the workflow uses `the legacy deployment project` but `.firebaserc` targets `the prior configured hosting project`.
2. **React and Vue framework integration guides are actively broken** — wrong event names and wrong detail shapes that will silently fail in consumer code.
3. **Three accessibility violations block release under WCAG AA** — `diwa-tabs` has no keyboard navigation, `diwa-switch` has no accessible name, and `diwa-popover` misuses `role="tooltip"`.
4. **React wrapper build is non-idempotent** — a second build run in the same workspace fails due to a patch script that mutates tracked source files.

## Section 1 · CI / Release Pipeline

*Agent: Diwa DS Release Automator + SDLC Lead*

---

### [P0] R-1 · Firebase `projectId` mismatch — every deploy lands on the wrong project

**File:** The former hosting workflow.
**Conflict:** The workflow and local deploy configuration pointed to different hosting projects.
**Impact:** All automated deploys of the storefront currently publish to a different Firebase project than intended. Production users see stale or absent content.  
**Fix:** Set `projectId: the prior configured hosting project` in the deploy workflow to match `.firebaserc`.

---

### [P0] R-2 · Deploy fires in parallel with CI — broken commits ship before tests pass

**Files:** [.github/workflows/ci.yml](.github/workflows/ci.yml#L6) and the former hosting workflow.
**Issue:** Both workflows trigger on `push: main`. CI and deploy run concurrently; a commit that fails CI can still complete a deploy to production.  
**Fix:** Change deploy trigger to `workflow_run` on CI workflow success:
```yaml
on:
  workflow_run:
    workflows: ["CI"]
    types: [completed]
    branches: [main]
jobs:
  deploy:
    if: ${{ github.event.workflow_run.conclusion == 'success' }}
```

---

### [P1] R-3 · Storefront build in CI skips stencil asset sync

**Files:** [package.json](package.json#L32), [.github/workflows/ci.yml](.github/workflows/ci.yml#L41), [scripts/sync-stencil-assets.cjs](scripts/sync-stencil-assets.cjs)  
**Issue:** CI runs `build:storefront` (plain `next build`) but `public/stencil/` is only populated in `build:storefront:release`. PRs can pass CI and then fail in the deploy-time release build.  
**Fix:** Replace `build:storefront` with `build:storefront:release` in all CI jobs.

---

### [P1] R-4 · `pnpm-smoke` CI job skips test, test:ux, and type-check

**File:** [.github/workflows/ci.yml](.github/workflows/ci.yml)  
**Issue:** pnpm-path contributors bypass the test gate entirely — a build-passing, test-failing state is invisible on the pnpm install path.  
**Fix:** Add `pnpm --filter @diwa-design-system/components run test`, `test:ux`, and `type-check` steps to the `pnpm-smoke` job.

---

### [P1] R-5 · `hosting-smoke-check.cjs` is orphaned — never invoked

**Files:** [scripts/hosting-smoke-check.cjs](scripts/hosting-smoke-check.cjs), [package.json](package.json)  
**Issue:** The script exists but has no `npm run smoke-check` alias and is referenced in no workflow. Post-deploy health verification is effectively absent.  
**Fix:** Add `"smoke-check": "node scripts/hosting-smoke-check.cjs"` to package.json scripts and call it as a post-deploy step in deploy-storefront.yml.

---

### [P2] R-6 · `sync-stencil-assets.cjs` deletes target before copy — non-atomic

**File:** [scripts/sync-stencil-assets.cjs](scripts/sync-stencil-assets.cjs)  
**Issue:** The script removes `public/stencil/` then runs `cpSync`. A failed copy leaves the directory empty — the storefront serves no Stencil assets until the next successful build.  
**Fix:** Stage files to a temp directory, then atomically rename/move to `public/stencil/` so the old content remains until the new copy is complete.

---

### [P2] R-7 · `alias-next-flight-files.cjs` skips existing aliases — stale aliases survive rebuilds

**File:** [scripts/alias-next-flight-files.cjs](scripts/alias-next-flight-files.cjs)  
**Issue:** The script only creates aliases if the target file does not exist. Stale aliases from a previous build are never refreshed, which can cause outdated RSC payload mappings to ship.  
**Fix:** Always overwrite alias targets on each build run.

---

### [P2] R-8 · `publish:all` has no dirty working-tree guard

**File:** [package.json](package.json)  
**Issue:** A release can be cut from uncommitted local state with no CI evidence. No `git status --porcelain` check protects the release.  
**Fix:** Add a `prerelease` script: `if [ -n "$(git status --porcelain)" ]; then echo 'Dirty tree — commit all changes before release.'; exit 1; fi`

---

### [P2] R-9 · GitHub Actions deploy action uses floating major tag

**File:** [.github/workflows/deploy-storefront.yml](.github/workflows/deploy-storefront.yml)  
**Issue:** `FirebaseExtended/action-hosting-deploy@v0` is a floating major-version tag. A silently-introduced breaking change upstream can break deploys without any change to this repository.  
**Fix:** Pin to the current SHA or a specific minor version (e.g. `@v0.9.0`).

## Section 2 · Web Components

*Agent: Diwa DS Web Components Engineer*

---

### [P1] WC-1 · Form integration documented but not implemented (diwa-select, diwa-multi-select)

**Files:** [diwa-select/diwa-select.tsx](diwa-components/src/components/diwa-select/diwa-select.tsx#L31), [diwa-multi-select/diwa-multi-select.tsx](diwa-components/src/components/diwa-multi-select/diwa-multi-select.tsx#L31)  
**Issue:** Both components document `name` and `required` props and claim form integration, but neither renders a hidden `<input>` nor uses `ElementInternals` / `formAssociated`. Fields do not submit their values in native `<form>` posts.  
**Fix:** Either implement `static formAssociated = true` + `ElementInternals.setFormValue()` to support native form association, or update the JSDoc/docs to explicitly state native form submission is unsupported and advise using controlled patterns.

---

### [P1] WC-2 · Combobox keyboard pattern incomplete — no `aria-activedescendant`, options are tabbable

**Files:** [diwa-select/diwa-select.tsx](diwa-components/src/components/diwa-select/diwa-select.tsx#L129), [diwa-multi-select/diwa-multi-select.tsx](diwa-components/src/components/diwa-multi-select/diwa-multi-select.tsx#L136), [diwa-select-option/diwa-select-option.tsx](diwa-components/src/components/diwa-select-option/diwa-select-option.tsx#L86)  
**Issue:** Internal highlighted-index state exists but `aria-activedescendant` is never set on the combobox trigger. Options are tabbable (`tabindex=0`), creating a noisy tab order instead of roving arrow-key navigation per the APG Combobox pattern.  
**Fix:** Assign deterministic IDs to rendered options; set `aria-activedescendant` on the trigger element to match the highlighted option's ID. Remove options from native tab order (`tabindex=-1`) and rely on `aria-activedescendant` + arrow key dispatch.

---

### [P1] WC-3 · Slotted label disconnected from `aria-labelledby` on combobox

**Files:** [diwa-select/diwa-select.tsx](diwa-components/src/components/diwa-select/diwa-select.tsx#L512), [diwa-multi-select/diwa-multi-select.tsx](diwa-components/src/components/diwa-multi-select/diwa-multi-select.tsx#L491)  
**Issue:** `aria-labelledby` is only set when the `label` prop exists. Consumers providing a label via the named `label` slot — a documented pattern — get a combobox with no accessible name.  
**Fix:** Bind `aria-labelledby` to the label container's ID whenever any label content is present (prop or slot). Add a fallback requiring `aria-label` when neither label prop nor slot content is provided.

---

### [P2] WC-4 · Blur event contract is partial — keyboard close paths do not emit

**Files:** [diwa-select/diwa-select.tsx](diwa-components/src/components/diwa-select/diwa-select.tsx#L386), [diwa-multi-select/diwa-multi-select.tsx](diwa-components/src/components/diwa-multi-select/diwa-multi-select.tsx#L358)  
**Issue:** `blur` is emitted only on click-outside close; Escape key and Tab-out close paths do not emit `blur`. Consumers depending on blur-equivalent lifecycle get inconsistent behavior by input modality.  
**Fix:** Define a consistent contract: either treat blur as a true focus-loss event (emit on all close paths) or introduce a `close` event with a `reason` payload (`click-outside | escape | tab | programmatic`). Apply consistently across both components.

---

### [P2] WC-5 · Hardcoded style values bypass token governance

**Files:** [diwa-table-head-cell/diwa-table-head-cell.tsx](diwa-components/src/components/diwa-table-head-cell/diwa-table-head-cell.tsx#L48), [diwa-radio-group-item/diwa-radio-group-item-styles.ts](diwa-components/src/components/diwa-radio-group-item/diwa-radio-group-item-styles.ts#L8), [diwa-multi-select-option/diwa-multi-select-option-styles.ts](diwa-components/src/components/diwa-multi-select-option/diwa-multi-select-option-styles.ts#L5)  
**Issue:** Inline animation/transition values and hardcoded pixel sizing exist in multiple component style files. These bypass the `--diwa-*` token system and silently resist density and theme customization.  
**Fix:** Move all hardcoded sizing and motion values to semantic token variables (`--diwa-*`). Apply via the existing style-generator functions, not inline styles.

---

### [P2] WC-6 · Inconsistent internal event naming across components

**Files:** [diwa-select-option/diwa-select-option.tsx](diwa-components/src/components/diwa-select-option/diwa-select-option.tsx#L54), [diwa-segmented-control-item/diwa-segmented-control-item.tsx](diwa-components/src/components/diwa-segmented-control-item/diwa-segmented-control-item.tsx#L41), [diwa-table-head-cell/diwa-table-head-cell.tsx](diwa-components/src/components/diwa-table-head-cell/diwa-table-head-cell.tsx#L22)  
**Issue:** Internal (parent-child) events use at least three different naming conventions: camelCase prefixed, kebab-case prefixed, and unprefixed. This increases wrapper complexity and consumer confusion.  
**Fix:** Standardize on one internal event convention (e.g. `diwa-<component>:<event>`), document the boundary between internal and public events, and create a migration path for legacy names.

## Section 3 · Framework Wrappers

*Agent: Diwa DS Wrapper Maintainer*

---

### [P0] W-1 · React wrapper build is non-idempotent — second run fails

**Files:** [diwa-components-react/scripts/patch-generated-react-lib.cjs](diwa-components-react/scripts/patch-generated-react-lib.cjs#L12), [diwa-components-react/src/react-component-lib/createComponent.tsx](diwa-components-react/src/react-component-lib/createComponent.tsx#L14)  
**Issue:** The prebuild patch script throws `"Pattern not found"` on a second consecutive run because it searches for unpatched source strings that no longer exist after the first patch. This breaks repeated local builds and CI reproducibility.  
**Fix:** Make the patch script idempotent (detect already-patched content and exit cleanly, or use an idempotent replace). Long-term: commit canonical helper sources once and remove the patching script entirely.

---

### [P1] W-2 · React and Vue dist declarations are effectively `any`-typed

**Files:** [diwa-components-react/dist/components.d.ts](diwa-components-react/dist/components.d.ts#L1), [diwa-components-vue/dist/components.d.ts](diwa-components-vue/dist/components.d.ts#L1)  
**Issue:** All generated React component exports are typed as `ForwardRefExoticComponent<any>` and all Vue exports as `DefineSetupFnComponent<any, ...>`. Angular proxies retain concrete types via `Components.Diwa*` interfaces, but React and Vue consumers lose all compile-time type safety for props and events.  
**Fix:** Fix declaration generation to retain concrete prop/event interfaces. Add type-level contract tests (`tsd` or compile fixtures) asserting known prop/event types for representative components. Treat `any` in wrapper dist declarations as a release blocker.

---

### [P2] W-3 · Native DOM event name collisions in wrapper surface

**Files:** [diwa-button/diwa-button.tsx](diwa-components/src/components/diwa-button/diwa-button.tsx#L83), [diwa-input/diwa-input.tsx](diwa-components/src/components/diwa-input/diwa-input.tsx#L85), [diwa-select/diwa-select.tsx](diwa-components/src/components/diwa-select/diwa-select.tsx#L106)  
**Issue:** Multiple components emit events named `click`, `change`, `input`, `focus`, `blur` — same as native DOM events. Stencil build already emits warnings about these conflicts. In React and Vue (where all events are `any`-typed), this creates integration ambiguity.  
**Fix:** Plan a semantic event naming migration (`valueChange`, `selectionChange`, etc.) with a deprecation bridge for a semver-major release cycle. Add wrapper-level event contract tests validating event detail payloads.

---

### [P2] W-4 · Angular `DIRECTIVES` export not in public API

**File:** [diwa-components-angular/src/public-api.ts](diwa-components-angular/src/public-api.ts#L5)  
**Issue:** `DIRECTIVES` array is defined in `src/directives/index.ts` but not re-exported from `public-api.ts`. Consumers wanting bulk directive registration cannot import it from the package root.  
**Fix:** Export `DIRECTIVES` from `public-api.ts` if bulk registration is intended support surface. Otherwise document that only per-component proxies are public.

## Section 4 · Accessibility (WCAG 2.1 AA)

*Agent: Diwa DS Accessibility Auditor*

---

### [P1] A-1 · `diwa-tabs` — No keyboard navigation in tablist (WCAG 2.1.1)

**File:** [diwa-tabs/diwa-tabs.tsx](diwa-components/src/components/diwa-tabs/diwa-tabs.tsx#L62)  
**Issue:** Correct roving `tabindex` is implemented but there is no `@Listen('keydown')` handler for `ArrowLeft`, `ArrowRight`, `Home`, or `End`. Keyboard users cannot move between tabs. Note: `diwa-tabs-bar` (sibling) correctly implements this; `diwa-tabs` (integrated) does not.  
**Fix:** Add a `@Listen('keydown')` handler implementing the full APG Tabs keyboard pattern (Arrow navigation, Home/End, focus management).

---

### [P1] A-2 · `diwa-switch` — `role="switch"` has no accessible name (WCAG 4.1.2)

**File:** [diwa-switch/diwa-switch.tsx](diwa-components/src/components/diwa-switch/diwa-switch.tsx#L46)  
**Issue:** The `role="switch"` element's accessible name is computed only from its DOM children (thumb/spinner). The slotted label text is in a sibling `<span>`, not associated via `aria-labelledby`. Screen readers announce "switch" with no label.  
**Fix:** Assign a unique label ID to the label element. Set `aria-labelledby={labelId}` on the `role="switch"` element.

---

### [P1] A-3 · `diwa-popover` — `role="tooltip"` on a click-triggered panel (WCAG 4.1.2)

**File:** [diwa-popover/diwa-popover.tsx](diwa-components/src/components/diwa-popover/diwa-popover.tsx#L67)  
**Issue:** `role="tooltip"` must only be used for hover/focus supplemental descriptions, never for click-toggled interactive panels. The current pattern also produces conflicting `aria-haspopup="true"` semantics and incorrectly hides the "tooltip" with `aria-hidden="true"`.  
**Fix:** Replace with a disclosure pattern: `aria-expanded` + `aria-controls` on the trigger; `role="region"` with `aria-label` on the panel.

---

### [P2] A-4 · `diwa-multi-select` — `role="dialog"` on a non-modal dropdown (WCAG 4.1.2)

**File:** [diwa-multi-select/diwa-multi-select.tsx](diwa-components/src/components/diwa-multi-select/diwa-multi-select.tsx#L430)  
**Issue:** The outer dropdown container uses `role="dialog"`, causing screen readers to announce a dialog context on dropdown open. This implies modality and focus-trap semantics that do not exist.  
**Fix:** Remove `role="dialog"` from the container. The inner `role="listbox"` is sufficient.

---

### [P2] A-5 · `diwa-segmented-control` — Wrong ARIA pattern (WCAG 1.3.1, 4.1.2)

**Files:** [diwa-segmented-control/diwa-segmented-control.tsx](diwa-components/src/components/diwa-segmented-control/diwa-segmented-control.tsx#L80), [diwa-segmented-control-item/diwa-segmented-control-item.tsx](diwa-components/src/components/diwa-segmented-control-item/diwa-segmented-control-item.tsx#L49)  
**Issue:** Uses `role="group"` + `aria-pressed` — the toggle-button pattern. A segmented control is mutually exclusive single-selection, which should use `role="radiogroup"` + `role="radio"` + `aria-checked`. Arrow key navigation is also absent.  
**Fix:** Replace with `role="radiogroup"` (container) and `role="radio"` + `aria-checked` (items). Add `ArrowLeft`/`ArrowRight` handler for APG Radio Group keyboard pattern.

---

### [P2] A-6 · `diwa-table-head-cell` — Sort button has no focus ring; reduced-motion bypass (WCAG 2.4.7, 2.3.3)

**File:** [diwa-table-head-cell/diwa-table-head-cell-styles.ts](diwa-components/src/components/diwa-table-head-cell/diwa-table-head-cell-styles.ts)  
**Issue:** The `.sort-btn` CSS block has `outline-offset` but no `outline` rule and no `getFocusStyle()` call. The sort-direction SVG uses an inline `transition` style that cannot be overridden by `getReducedMotionStyle()`.  
**Fix:** Add `${getFocusStyle('.sort-btn')}` and `${getReducedMotionStyle('.sort-btn')}` to styles. Move SVG transition to a CSS class so the reduced-motion block can override it.

---

### [P2] A-7 · Light-theme color token contrast failures (WCAG 1.4.3)

**File:** [global/app.css](diwa-components/src/global/app.css#L579)  

| Token | Current Value | Contrast on White | Required | Status |
|---|---|---|---|---|
| `--diwa-text-muted` (light) | `#777777` | 3.97:1 | 4.5:1 | ✗ FAIL |
| `--diwa-warning-text` (light) | `#b8830a` | 3.10:1 | 4.5:1 | ✗ FAIL |
| `--diwa-accent` (light, text use) | `#0f8a7b` | 4.08:1 | 4.5:1 | ✗ FAIL |

**Fix:**
```css
--diwa-text-muted:   #6b6b6b;  /* ~4.6:1 on white */
--diwa-warning-text: #7c5700;  /* 4.5:1 on white */
/* Restrict --diwa-accent in light theme to non-text (borders, icons) */
```

---

### [P2] A-8 · `diwa-banner` — Live region does not re-announce on show (WCAG 4.1.3)

**File:** [diwa-banner/diwa-banner.tsx](diwa-components/src/components/diwa-banner/diwa-banner.tsx#L210)  
**Issue:** Banner content is pre-populated in the DOM while `aria-hidden="true"`. When `visible` changes from `false→true`, the `aria-hidden` is removed but no content change fires inside the live region — AT does not re-announce the message.  
**Fix:** Keep the live region element empty while hidden. Inject message content via a `@Watch('visible')` handler one rAF after the element becomes visible, so the live region fires on content injection.

---

### [P3] A-9 · `diwa-popover` — Default trigger button has no accessible name (WCAG 4.1.2)

**File:** [diwa-popover/diwa-popover.tsx](diwa-components/src/components/diwa-popover/diwa-popover.tsx#L54)  
**Issue:** Default trigger renders an `aria-hidden` SVG with no text and no `aria-label`.  
**Fix:** Add `aria-label="More information"` to the default trigger button.

---

### [P3] A-10 · `diwa-select` / `diwa-multi-select` — Error state uses polite live region (WCAG 4.1.3)

**Files:** [diwa-select/diwa-select.tsx](diwa-components/src/components/diwa-select/diwa-select.tsx#L571), [diwa-multi-select/diwa-multi-select.tsx](diwa-components/src/components/diwa-multi-select/diwa-multi-select.tsx#L545)  
**Issue:** `role="status"` (polite) is used for error messages. Form validation errors should be assertive (`role="alert"`) so users are notified immediately.  
**Fix:** `role={this.state === 'error' ? 'alert' : 'status'}`.

## Section 6 · Storefront Documentation

*Agent: Diwa DS Storefront Developer + Technical Writer*

---

### [P0] D-1 · Framework guides: React event name and detail shape are wrong (`DSelect`)

**File:** [storefront/src/app/developing/_shared/frameworkGuides.ts](diwa-components/storefront/src/app/developing/_shared/frameworkGuides.ts)  
**Issue:** React guide shows `onUpdate` + `{ value: string }`. `diwa-select` emits `change` with `{ name: string; value: string }`. Consumer code copied from this guide silently fails.
